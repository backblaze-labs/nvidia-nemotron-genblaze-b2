# Plan — `b2-nvidia-storyforge`

A from-scratch Genblaze-based B2 sample that exercises **every free
modality on `build.nvidia.com`** through one Genblaze pipeline on a single
`nvapi-` key, with Backblaze B2 as the asset store.

## 1. Purpose

`b2-nvidia-storyforge` shows how cheaply a multi-modal generative-media app
becomes when storage + orchestration are delegated to Genblaze. One user
prompt ("a lighthouse keeper befriends a sea otter") produces a fully
illustrated, narrated short story with a mood soundtrack — all generated
through `genblaze-nvidia` providers, all assets persisted to B2 by
`genblaze-s3`, and all of it fronted by a Next.js page styled with the
visual tokens from `vibe-coding-starter-kit`.

It's the four-modality answer to "what do I get for an `nvapi-` key and a
B2 bucket": chat (LLM story expansion) → image (per-chapter illustrations,
fan-out) → audio TTS (per-chapter narration, fan-out) → audio music (one
ambient mood score). The Cosmos video step is wired in best-effort and
gracefully reports `AUTH_FAILURE` when the free-tier key lacks Cosmos
access, so the sample stays useful even when video isn't available.

This is the cheap-generative-media-app framing the Genblaze ethos calls
for: zero custom infrastructure, every Genblaze call replacing what would
otherwise be ~200 lines of `requests` + `boto3` + retry boilerplate.

## 5. Genblaze surface

- `Pipeline("b2-nvidia-storyforge", max_concurrency=3)` — slug IS the
  provenance signal.
- `S3StorageBackend.for_backblaze(bucket, region=, key_id=, app_key=,
  auto_lifecycle=True)` — explicit kwargs; never let `B2_APP_KEY` env
  fallback fire.
- `ObjectStorageSink(backend, prefix="storyforge", key_strategy=KeyStrategy.HIERARCHICAL)`.
- `LoggingTracer()` always; `OTelTracer(endpoint=…)` when `OTEL_ENDPOINT` set;
  combined via `CompositeTracer`.
- `StepCache(settings.step_cache_dir)` for local re-run dev loops.
- Providers: `NvidiaImageProvider`, `NvidiaAudioProvider`, `NvidiaVideoProvider`
  (best-effort), and `genblaze_nvidia.chat()` for the LLM story-expansion step.
- Idiomatic shape used:
  - **Sequential**: `Pipeline(...).step(chat-llm).step(...)` — the first
    step's output (a JSON story spec) feeds the next stage's prompts.
    Note: `chat()` is a standalone helper, not a `Provider`, so step 1 is
    actually a thin "expand" call wrapped in a `step`-compatible shape. See
    Reference snippets §10 for the idiom — we emit a single
    `Pipeline.step(NvidiaChatStepProvider, ...)` shim where the shim is a
    small Provider subclass living *in `repo/pipelines.py`* (not in a new
    package). If the builder finds Genblaze ships a first-class
    `NvidiaChatProvider` by build time, prefer that over the shim and
    drop the shim — note the change in the builder summary.
  - **Fan-out (3× chapters)**: three sibling `.step(NvidiaImageProvider, …)`
    calls wired with `input_from=0` + `max_concurrency=3` to share the
    chat output but run in parallel.
  - **Fan-out (3× narrations)**: same pattern with `NvidiaAudioProvider`
    + `model="nvidia/riva-tts"`.
  - **Single trailing step**: `.step(NvidiaAudioProvider, model="nvidia/fugatto", …)`
    for the mood music — one stereo track, prompt derived from the chat
    output's `mood` field.
  - **Best-effort tail**: optional `.step(NvidiaVideoProvider, …)` only
    when the request body says `include_video=True`. Catch
    `ProviderError(error_code=AUTH_FAILURE)` at the FastAPI handler and
    return the partial Run with a `video_skipped: "auth_required"` note
    in the response payload — the rest of the assets stay valid.

## 6. B2 surface

Effectively none in sample source. All reads/writes happen inside
`genblaze-s3`. UA delegation is satisfied by
`b2ai-genblaze/<version>` (set by the library on its internal boto3
client) plus the `Pipeline(name="b2-nvidia-storyforge")` slug carried in
every Manifest. **`b2-doctor` check #2 exception applies.**

The only B2-adjacent surface in our code is presigning chapter assets for
the frontend — done via `backend.get_url(key, expires_in=…)` from inside
`repo/pipelines.py`.

## 7. Ethos constraints (re-stated for the builder — non-negotiable)

- `Pipeline(name="b2-nvidia-storyforge")` everywhere.
- **No direct `boto3` / `botocore` import anywhere in sample source.** A
  structural test (`tests/test_structure.py`) asserts this with an AST
  walk of `app/`.
- FastAPI handlers return Genblaze `Run` / `Step` / `Asset` Pydantic
  models directly. The only custom request DTOs are inputs (prompt, opts).
- `.env.example` uses `B2_APPLICATION_KEY` (parent standard).
  `S3StorageBackend.for_backblaze(...)` called with explicit `key_id=`
  and `app_key=` kwargs so `B2_APP_KEY` env fallback never fires.
- Genblaze imports confined to `services/api/app/repo/pipelines.py`.
- **Size targets:** `repo/pipelines.py` < 100 lines (excluding docstring
  and imports); `services/api/app/` ≤ 400 lines total.

## 8. Key features

- **One prompt → fully produced story.** Title, 3 chapters of narration
  text, 3 illustrations, 3 narrated audio tracks, one ambient music
  track. All in a single Genblaze pipeline run.
- **Every free build.nvidia.com modality, one key.** Chat (Llama 3.3 70B
  default, configurable to Nemotron / Mistral / Qwen), Image (FLUX.1
  Schnell default, configurable to SD 3.5 / SDXL), TTS (Riva), Music
  (Fugatto). Cosmos video as best-effort.
- **Live SSE pipeline progress.** The frontend subscribes to the
  Pipeline's `.stream()` events and shows each step transition in
  realtime — no custom websocket layer, the runtime handles it.
- **All assets in B2 with hierarchical keys.** Story chapters land at
  `storyforge/<run-id>/chapter-<n>/{illustration.png,narration.wav}` and
  `storyforge/<run-id>/music.wav` — one folder per run, easy to
  share/audit/clean.
- **Best-effort video tail.** Adds Cosmos video2world if the key has
  access; otherwise emits a structured `video_skipped` marker in the
  response and the rest of the run continues green.
- **Self-documenting pipeline manifests.** `ObjectStorageSink` writes
  `manifest.json` per run with the full Pipeline name, model ids,
  prompts, and asset list — provenance for every generated artifact.

## 10. Reference snippets (anchored to live `genblaze-nvidia` 0.2.0 shape)

**Backend singleton** (`repo/pipelines.py`, top):

```python
from functools import lru_cache
from genblaze_core import (
    CompositeTracer, KeyStrategy, LoggingTracer, Modality,
    ObjectStorageSink, OTelTracer, Pipeline, StepCache,
)
from genblaze_s3 import S3StorageBackend
from genblaze_nvidia import (
    NvidiaImageProvider, NvidiaAudioProvider, NvidiaVideoProvider, chat,
)
from app.config import settings

PIPELINE_NAME = "b2-nvidia-storyforge"

@lru_cache(maxsize=1)
def _backend() -> S3StorageBackend:
    return S3StorageBackend.for_backblaze(
        settings.b2_bucket_name,
        region=settings.b2_region,
        key_id=settings.b2_key_id,
        app_key=settings.b2_application_key,   # explicit; bypasses B2_APP_KEY fallback
        auto_lifecycle=True,
    )

def _sink() -> ObjectStorageSink:
    return ObjectStorageSink(_backend(), prefix="storyforge",
                             key_strategy=KeyStrategy.HIERARCHICAL)
```

**Story-expansion shim** (in-file Provider subclass — drop if a
first-class `NvidiaChatProvider` lands upstream):

```python
import json
from genblaze_core.models.asset import Asset
from genblaze_core.models.enums import Modality
from genblaze_core.providers.base import SyncProvider, ProviderCapabilities

class NvidiaChatStepProvider(SyncProvider):
    """Adapt genblaze_nvidia.chat() into a Pipeline.step()-compatible Provider.

    Returns a single text Asset whose body is the raw LLM JSON.
    """
    name = "nvidia-chat"
    capabilities = ProviderCapabilities(modalities=(Modality.TEXT,))

    def generate(self, step, config):
        resp = chat(step.model, prompt=step.prompt, system=step.params.get("system"))
        return [Asset.text(content=resp.text, mime_type="application/json")]
```

**Pipeline construction** (one function in `repo/pipelines.py`):

```python
def build_storyforge_pipeline(
    seed_prompt: str,
    *, chat_model: str, image_model: str,
    include_video: bool, video_model: str | None,
) -> Pipeline:
    p = (
        Pipeline(PIPELINE_NAME, max_concurrency=3)
        .tracer(CompositeTracer([LoggingTracer()]))
        .cache(StepCache(settings.step_cache_dir))
        .step(  # 1. chat — expand seed into structured story
            NvidiaChatStepProvider(),
            model=chat_model, modality=Modality.TEXT,
            prompt=_STORY_EXPANSION_PROMPT.format(seed=seed_prompt),
            params={"system": "Return ONLY valid JSON matching the schema."},
        )
    )
    # 2-4. fan-out 3 illustration steps, sharing chat output as input
    for i in range(3):
        p = p.step(
            NvidiaImageProvider(), model=image_model, modality=Modality.IMAGE,
            input_from=0, max_concurrency=3,
            prompt_template="$.chapters[{i}].image_prompt".format(i=i),
            params={"aspect_ratio": "16:9", "cfg_scale": 4.5},
        )
    # 5-7. fan-out 3 narrations
    for i in range(3):
        p = p.step(
            NvidiaAudioProvider(), model="nvidia/riva-tts", modality=Modality.AUDIO,
            input_from=0, max_concurrency=3,
            prompt_template="$.chapters[{i}].narration".format(i=i),
        )
    # 8. mood music (single)
    p = p.step(
        NvidiaAudioProvider(), model="nvidia/fugatto", modality=Modality.AUDIO,
        input_from=0,
        prompt_template="$.mood_music_prompt",
    )
    # 9. best-effort video — appended only when requested
    if include_video and video_model:
        p = p.step(
            NvidiaVideoProvider(), model=video_model, modality=Modality.VIDEO,
            input_from=0,
            prompt_template="$.chapters[0].image_prompt",
            params={"aspect_ratio": "16:9"},
        )
    return p
```

**Note for the builder:** the exact `prompt_template` / `input_from`
plumbing above reflects the *intended* idiom. If the live
`genblaze-core` 0.2.4 API differs (e.g. uses `from_prev` / a callable
prompt-mapper), follow the live shape — the smoke-test import will fail
fast and you'll re-read `genblaze-core`'s README. **Do not paper over a
mismatch with custom glue code; that defeats the ethos.**

**FastAPI handler** (`app/main.py` — returns Genblaze types directly):

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from genblaze_core.exceptions import ProviderError
from genblaze_core.models.enums import ProviderErrorCode
from app.repo.pipelines import build_storyforge_pipeline, _sink
from app.types.api import StoryRequest

app = FastAPI(title="b2-nvidia-storyforge")

@app.post("/runs/stream")
def stream_run(req: StoryRequest):
    pipe = build_storyforge_pipeline(
        req.prompt, chat_model=req.chat_model, image_model=req.image_model,
        include_video=req.include_video, video_model=req.video_model,
    )
    return StreamingResponse(_to_sse(pipe.stream(sink=_sink(), timeout=600)),
                             media_type="text/event-stream")

@app.post("/runs")
def run(req: StoryRequest):
    pipe = build_storyforge_pipeline(
        req.prompt, chat_model=req.chat_model, image_model=req.image_model,
        include_video=req.include_video, video_model=req.video_model,
    )
    try:
        return pipe.run(sink=_sink(), timeout=600).run   # genblaze Run model
    except ProviderError as e:
        if e.error_code == ProviderErrorCode.AUTH_FAILURE and req.include_video:
            # Re-run without video — user knows their key lacks Cosmos access.
            req.include_video = False
            return run(req)
        raise
```
